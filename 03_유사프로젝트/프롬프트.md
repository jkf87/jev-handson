## ① jev-ultrafast로 구글 항공권 찾기

```prompt 1
이 폴더에서 jev-ultrafast로 구글 항공권을 찾아 줘. 순서는 README.md 「실습 ①」 그대로.
git clone https://github.com/browser-use/jev-ultrafast 로 받아 uv sync 하고 jev-ultrafast/.env를 만들어 줘.
TYPESAFE_API_KEY는 이 폴더 .env에서 옮기고(값 출력 금지), 글자 도우미는 README대로 로컬 Ollama qwen3.5:4b로.
bash ultrafast/start_chrome.sh 로 평소 Chrome과 분리된 임시 Chrome을 띄우고, BU_NAME=jevlecture BU_CDP_URL=http://127.0.0.1:9333 을 붙여
ultrafast/run_flights.py로 서울→제주 3주 뒤 편도를 찾아 줘(예약·선택은 하지 마).
끝나면 걸린 시간·동작 수·Jev 판단 수를 보여 주고 final.png를 열어 확인해 줘.
```

- 예제 코드: `code/ultrafast/run_flights.py` (원본 저장소는 고치지 않고 실행 스크립트에서만 보정) · `code/ultrafast/start_chrome.sh`
- 기대 결과(9/23 강사 실행): 17.7초 · 동작 10번 · Jev 판단 18번 · 코드 검증 6/6 → `evidence/ultrafast/google-flights/`
- `BU_NAME`을 꼭 따로 줘요. 기본 데몬은 평소 쓰는 Chrome에 붙어 있을 수 있고, 그러면 `BU_CDP_URL`이 무시돼요. 스크립트가 시작 전에 확인하고 아니면 멈춰요
- 9/23 실측(63초): clone · uv sync · `.env`(키 값은 보여 주지 않고 옮김, 권한 600) → 임시 Chrome → 서울→제주 10/14 편도 **11.4초 · 동작 10번 · Jev 판단 19번 · 검증 6/6**. 글자 도우미(로컬 Qwen) "Seoul" 3.5초 · "Jeju-si" 0.7초. 기록: `evidence/prompts/1_구글항공권.jsonl` · `1_구글항공권_final.png`

## ② 네이버 항공권은 모바일 화면으로

```prompt 2
같은 방식으로 네이버 항공권도 찾아 줘. 이번엔 모바일 화면이야.
bash ultrafast/start_chrome.sh --mobile 로 임시 Chrome을 다시 띄우고 ultrafast/run_naver.py --show --mobile --viewport 430x932 로
서울→제주 3주 뒤 편도를 찾아 줘. 끝나면 ../evidence/ultrafast/naver_attempts_summary.json 을 읽고,
데스크톱 화면에서 9번 실패한 이유와 모바일에서 된 이유를 smart if(--done-min-p)까지 넣어 설명해 줘.
```

- 예제 코드: `code/ultrafast/run_naver.py` (입력 뒤 0.8초 대기 · 날짜 버튼 이름 보강 · DONE 확률 0.6 미만이면 기다리기)
- 기대 결과(9/23 강사 실행): 8.5초 · 동작 6번 · Jev 판단 11번 · 검증 5/5 → `evidence/ultrafast/naver-mobile-timing/`
- 네이버 달력은 안쪽 스크롤 상자라 처음 보이는 달의 날짜만 고를 수 있어요. 날짜는 이번 달이나 다음 달로
- 9/23 실측(273초): **첫 실행은 실패**했어요. 새 프로필이라 네이버가 전체 화면 이벤트 팝업을 띄웠고, 그 투명 레이어가 폼을 덮었어요. Jev는 요소 표만 보니 뒤의 '도착지'를 0.86 이상으로 120번 골랐고, 클릭 직전 검사가 매번 취소했어요(실행 0번). 에이전트가 원인을 찾아 `run_naver.py`에서 지금 누를 수 없는 요소를 표에서 빼게 고쳤고(배포본에 반영, 끄려면 `--keep-covered`), 다시 돌리니 첫 판단이 '닫기' → **8.0초 · 동작 9번 · 판단 10번 · 검증 5/5**. DONE 0.47 · 0.43은 WAIT로 바뀌었다가 0.96에서 끝남
- 요약 파일의 13회가 데스크톱 9회 + 모바일 4회라는 것도 에이전트가 짚어 줘서 슬라이드·README를 바로잡았어요(시험 때 프롬프트는 "13번"). 기록: `evidence/prompts/2_네이버모바일.jsonl` · `2_네이버모바일_final.png` · 고친 코드 `에이전트가_고친_코드/run_naver.py.diff`

```prompt 5
usecases 폴더의 예제 세 개를 돌려 줘(키는 이 폴더 .env): pick_element.mjs · game_move.mjs · robot_action.mjs.

기대와 다른 건이 있으면 질문 문구를 고칠지 코드 규칙으로 막을지 나눠서 제안하고,
규칙 쪽이면 고친 뒤 방금 기록을 --replay로 다시 돌려 확인해 줘. 정답을 코드에 박아 넣지는 마.
```

- 예제 코드: `code/usecases/` (`pick_element.mjs` 요소 표 · `game_move.mjs` 틱택토 · `robot_action.mjs` 센서 글 · `jev.mjs` 공통)

- 9/23 실측(72초): 10건 중 9건 기대대로(컴퓨터 유즈 3/3 · 게임 3/3 · 로봇 3/4). 틀린 로봇 건은 "배터리는 숫자 하나로 끝나는 안전 조건"이라며 코드 규칙으로 고침(15% 미만이면 충전하러, 부딪칠 위험이 먼저) → 방금 기록 `--replay` 4/4, 앞 기록도 4/4. 게임 이기기 0.54 · 막기 0.51, 결제 위험 0.65는 문턱에 가까우니 질문 문구를 고치자고 제안만 함. 고친 코드: `evidence/prompts/에이전트가_고친_코드/robot_action.mjs`
